# lab2 · 能力目标与接口约定（陷入与中断：系统调用与控制台交互）

> **增量包版本**：v1（2026-09-07），由课程组统一发放。

> 内核目前已具备基础启动与字符输出能力。本实验将使其具备**中断与异常处理及现场恢复**能力：
  实现用户态（U 态）与内核态（S 态）的安全切换、响应时钟与 UART 中断、处理系统调用，
  并成功运行第一个用户态程序（sh）。
  本阶段允许采用简化的调度逻辑——内核处理完成后直接返回原进程；完整的多任务上下文切换与调度机制将在 lab4 中系统实现。

## 1. 能力目标（由你设计并实现）

1. trampoline 机制实现：U 态与 S 态切换时 sp 与 sscratch 寄存器的安全交换、trapframe 的
   保存与恢复（trampoline.S 构成了底层汇编支撑，其注释即为详细规范）。
2. usertrap 处理：系统调用分发（含 sepc 寄存器合理前移语义）与中断分发。
3. 系统调用参数传递：argint/argaddr/argstr 等参数提取函数（命名可自定）。
4. 中断驱动控制台与输入缓冲：依据你的 `LAB2_BUF_SEMANTICS`（行缓冲/
   字符流）、`LAB2_BUF_SIZE`、`LAB2_TICK` 设计缓冲区结构与进程唤醒机制。
5. 最小进程支撑机制：满足基础执行流管理——足以支撑"运行 sh、sh fork 出子进程运行
   hi/spin、wait 回收子进程"。（本阶段暂未开启分页：采用 `satp=0` 直接映射加 PMP 内存物理保护
   作为合法过渡方案，lab3 将正式开启 SV39 分页机制。）
6. sys_exec 从**内嵌程序表**加载程序映像（见 §2.4；真实磁盘与文件系统驱动
   将在 lab6 中实现）。

## 2. 接口约定与核心规范

1. **ecall ABI 规范**：a7=调用号，a0–a2 传递参数，a0 存放返回值；用户侧存根由
   `user/usys.pl` 生成——**系统调用号表即为统一接口规范**，内核侧分发必须
   与之一致；对未知/未实现的系统调用号必须返回确定错误（-1），
   不得发生内核 panic。
2. **trampoline 规范**：TRAMPOLINE 与 TRAPFRAME 虚拟地址映射及切换机制，
   详见 kernel/trampoline.S 头部注释。
3. **exec 接口形式**：保持标准 xv6 接口 `exec(name, argv)`；lab2 阶段性简化允许
   忽略 argv 参数（内嵌程序均无参数）——将在 lab5 中完善完整参数解析与压栈。
4. **内嵌程序表规范**（Makefile.upgrade 自动生成 `kernel/userimg.S`）：
   `_uprog_table` 每项 = `{u64 start; u64 end; char name[]}`（.balign 8），
   以 `{0,0}` 结尾；程序为基址 0 的平铺二进制映像。
5. **系统运行与验收规范**：`make qemu` 启动后进入 sh 提示符；`support/inject_uart.py`
   模拟终端输入一行命令能正确解析执行并正确回显。

## 3. 设计决策（设计笔记必须明确回答；现场验收重点考查）

- trapframe 的存储位置与大小，采用每进程独立结构还是全局结构？由谁在何时负责切换？
- 输入缓冲的数据结构与锁机制；控制台读取中"状态检查-休眠等待"如何具体实现；
  行缓冲与字符流在边界处理和换行上的语义差异具体体现在哪几行代码？
- 系统调用分发表的组织形式（switch-case / 表驱动 / 宏展开生成）及统一错误码规范。
- 在尚未引入虚拟内存页表的前提下，fork 如何安全复制用户程序镜像？复制到哪里、由谁记账？
- 用户空间指针在当前直接映射阶段允许**直接解引用**——该简化实现必须在 lab3 引入页表后重构为安全的受控内存拷贝。

## 4. 预置支撑代码（gifts/，保持只读）

trampoline.S、usys.pl、user.h、ulib.c、printf.c（用户态基础库）；
课程自制辅助文件：sh.c、hi.c、spin.c、user.ld、Makefile.upgrade
（用户程序内嵌方案：UPROGS 编译为平铺二进制并通过 .incbin 指令嵌入内核）。
Makefile 合并：把 Makefile.upgrade 的规则并入你的 Makefile，
并把 `kernel/userimg.o` 加进 OBJS 目标列表；三个固定参数保持不动。

## 5. 里程碑自检

1. `make qemu` 进入 `sh>`，键入 `hi`（或通过 inject_uart 自动输入）输出有效进程 PID；
2. `spin` 运行时敲击键盘，内核输出与程序输出交错显示且无死锁或混乱；
3. 非法系统调用号（改一行 usys 临时验证后还原）稳定返回 -1 而非导致死机。

**回归验证**：个性化 Banner 依然随系统启动正常打印（验证 lab1 字符输出通道未被破坏）。

## 6. 耗时参考

  （输入缓冲边界与语义，行/字符流通用）已随包交付，见 `support/tests/README-tests.md`。

  （exec/exit/fork/wait）全部有对应存根。**核对通过。**
